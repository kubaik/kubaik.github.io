AdSense Compliance Audit — Changelog
=====================================
Date: 2026-10-29 (update)
Scope: Stop tombstone recreation after delete

Root cause
----------
`utilsIndexing/retire_registry.py` (invoked from StaticSiteGenerator.generate_site
on every `blog_system.py build`) maintains:
  - published_slugs.json  (every slug that has ever been live)
  - retired_slugs.json    (slugs no longer live)

On the next build it detects “in ledger but no post.json” and rewrites a
noindex tombstone index.html for any slug still inside the tombstone_days
window (default 180). That is why the 24 deleted directories reappear
after deployment.

Fix
---
adsense_compliance_audit.py (v3.1)
- When --delete is used, after `git rm` the script now also removes every
  deleted slug from both published_slugs.json and retired_slugs.json.
- The updated ledger files must be committed together with the deletions.
- Next build will no longer recreate the tombstones.

Files to replace
----------------
- adsense_compliance_audit.py  (updated below)
- (optional) the four files from the previous delivery if not already applied

Usage
-----
python adsense_compliance_audit.py --delete --force
# then commit the deleted docs/ dirs AND the two updated JSON ledgers
git add docs/ published_slugs.json retired_slugs.json
git commit -m "Permanently remove tombstoned low-quality posts"
git push
