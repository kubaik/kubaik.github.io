ROUND 3 — SCRIPTS NOW SCAN docs/ THEMSELVES (no verdict files needed)
  * triage.py exposes analyze(docs): reviews EVERY content directory under docs/ and returns DELETE/IMPROVE rows.
    delete_posts.py, improve_posts.py and post_enhancer.py call it on every run, so results always reflect what is
    currently in docs/. --verdicts / --list remain as optional overrides only.
  * Coverage is printed each run: "reviewed N post directories (skipped K site/reserved dirs ...)". Directories with a
    missing/corrupt post.json are still reviewed from index.md (and flagged, e.g. as thin); legal/site pages
    (about, contact, privacy, terms, ai-content-policy, tag, author, static) are skipped by name.
  * delete_posts.py re-scans after each pass until nothing new is flagged (deleting one half of a duplicate pair can
    change which sibling is flagged: 86 posts on pass 1, +1 on pass 2). --max is a total budget. New --force-slug
    deletes a post the scan did not flag.
  * improve_posts.py: the REVIEW always covers every post; --limit only bounds LLM rewrites per run (default 10,
    --all or --limit 0 = everything). Prints "N of M pending, K remain". Skips posts flagged DELETE and warns.
  * blog-automation.yml no longer passes verdict files to any step.
  * Verified on a repo copy with NO report files present, including injected edge cases (markdown-only dir, corrupt
    post.json with/without index.md, empty dir): all reviewed or skipped correctly; delete is idempotent.

NEW FILES (copy to repo root)
  delete_posts.py     Deletes every DELETE-verdict post. Dry run by default; --confirm to act; --max N per run;
                      --slug X for one post. Backs up to .triage_backups/, removes docs/<slug>/ and its OG images,
                      records docs/_removed_posts.json, REPAIRS links in remaining posts that pointed at deleted
                      posts, and writes blocked_topics.json so the topic can never be regenerated. Idempotent.
  improve_posts.py    LLM rewrite of IMPROVE posts using the pipeline's existing provider chain (no new secrets).
                      Rewrites to remove first-person/invented evidence/unverifiable products, keeps correct code.
                      Output is VALIDATED (fabrication density, entity gate, min length, code retained, balanced
                      fences, no H1, no links, title/meta sanity); failures are retried with the reasons fed back;
                      if still failing the ORIGINAL IS KEPT and logged to improve_report.json. Backs up
                      post.json.pre_llm, stamps llm_improved_at (resume-safe), rewrites index.md, then runs
                      post_enhancer.py. Bounded: --limit N (default 10), worst offenders first.
  quality_gate.py     Single source of truth used by generation, delete and improve: blocklist (blocked_topics.json),
                      topic gate (first-person, numeric-outcome and incident-narrative topics), post gate
                      (fabrication density + deleted-title match).
  entity_gate.py      Flags versioned products that cannot be verified (offline allow-list; PyPI/npm online check).
  triage.py           Report-only verdicts. (--apply-delete removed: it did not write the blocklist.)
  post_enhancer.py    Code-only IMPROVE pass: strips invented claims, replaces the false legacy footer, adds
                      related-reading + official-docs links, repairs dead internal links. Idempotent.

CHANGED FILES (full files supplied)
  blog_system.py
    - ROOT CAUSE FIXED: the generation prompt demanded "at least 3 concrete numbers (benchmarks, cost savings,
      error rates, salary ranges)", version-pinned tools, a table, an FAQ and EXACT headings in every post, so the
      model had to invent evidence. Replaced with grounding rules: no invented products/benchmarks/surveys, numbers
      only if documented, shown from assumptions, or labelled illustrative; no first-hand claims; structure follows
      the topic; headings are a SUGGESTED outline; FAQ/table/code only where they help.
    - Removed template headings that forced fake evidence ("Performance numbers from a live system", "Real results
      from running this", "Evidence and examples from real systems", "Resources that helped", ...).
    - Title-shape examples that modelled fabricated outcomes ("3 days lost to one missing depends_on", "Cut AWS costs
      40%") replaced with mechanism-first examples.
    - New post gates inside generate_blog_post(): unverifiable-product gate, fabrication-density gate, title-matches-
      deleted-post gate. A failing draft triggers a topic switch / retry exactly like the existing citation gate.
    - Blocklist: filter_safe_topics() now also drops claim-style topics and anything matching blocked_topics.json;
      PreFlightIndex indexes deleted posts so TF-IDF pre-flight blocks them; LLM topic-rescue output is validated.
    - Topic recycling fixed: when every topic duplicates an existing post the run now exits cleanly
      (TopicExhaustedError) instead of resetting to the UNFILTERED topic list.
    - New: `python blog_system.py topics expand [N]` asks the LLM for fresh topics, filters them through every gate
      (claim-style, blocklist, policy, duplicate), and appends them to config.yaml — supply for thousands of posts.
    - Footer template and intro lines no longer claim production experience or editorial review; "Last reviewed"
      refresh replaced by "Last generated".
  config.yaml          301 -> 170 topics: removed 93 first-person/numeric-claim topics, 29 near-duplicates and 9
                       incident-narrative topics. Added adsense_ads_enabled: false, adsense_loader_page_types,
                       ads_min_words, duplicate_similarity_threshold.
  seo_optimizer.py     AdSense loader only on home/article pages; manual ad units only on 1,200+ word articles and
                       only when adsense_ads_enabled is true; social links no longer doubled (full URL handling).
  static_site_generator.py  Passes page_type/word_count to the ad/meta helpers; deletes orphan sitemap-N.xml files
                       (listed ~1,200 dead URLs).
  velocity_controller.py  Caps restored to 1/2/2/2 per day with a hard ceiling of 3 and a clamped env override
                       (repo main had drifted to mature=25 / scaled=4).
  .github/workflows/blog-automation.yml  New bounded steps: triage -> delete_posts -> improve_posts -> post_enhancer
                       before the rebuild; new dispatch inputs triage_max_deletions (10) and improve_limit (5).

HOW TO RUN (one-time cleanup)
  python delete_posts.py                       # dry run: scans docs/, lists posts to delete
  python delete_posts.py --confirm             # deletes them (re-scans until stable) + writes blocked_topics.json
  python improve_posts.py --confirm --limit 10 # scans docs/, rewrites 10; repeat (resume-safe) or use --all
  python post_enhancer.py --docs docs --confirm
  (optional report: python triage.py --docs docs --out triage_report)
  python blog_system.py build && git add -A && git commit -m "quality cleanup"
  Or run the workflow manually with triage_max_deletions=100 and improve_limit=0..N.
